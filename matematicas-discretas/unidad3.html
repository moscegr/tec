3.1

Lógica Proposicional, Tablas de Verdad e Inferencias

1. Explicación Teórica y Conceptual

La Lógica Proposicional (o cálculo de enunciados) es el cimiento matemático del razonamiento deductivo y la toma de decisiones en ciencias de la computación. Estudia las proposiciones: oraciones declarativas que poseen un único valor de verdad bien definido, ya sea Verdadero (\(V = 1\)) o Falso (\(F = 0\)), sin ambigüedades subjetivas.

Intuición para Ingenieros de Software: En programación, cada bloque if (condición) evalúa una proposición booleana. Si conectamos múltiples condiciones con && (conjunción \(\land\)), || (disyunción \(\lor\)) o ! (negación \(\neg\)), estamos construyendo fórmulas proposicionales compuestas.

Una tabla de verdad evalúa exhaustivamente el resultado de una fórmula frente a las \(2^n\) posibles asignaciones de verdad (donde \(n\) es el número de proposiciones atómicas). Dependiendo del vector resultante en la columna principal, una expresión se clasifica en:

  • Tautología: Verdadera en todos los casos posibles (\(1\) en todas las filas). Representa verdades universales y teoremas.
  • Contradicción (Falacia): Falsa en todos los casos posibles (\(0\) en todas las filas). En software, representa código inalcanzable o bugs críticos (ej. if (x > 5 && x < 2)).
  • Contingencia: Verdadera para ciertas combinaciones y falsa para otras. Es el estado habitual de las decisiones dinámicas en un programa.
¿Por qué el condicional \(P \to Q\) es verdadero cuando \(P\) es falso?
Piensa en \(P \to Q\) como un contrato o promesa de API: "Si me entregas un token válido (\(P\)), te devuelvo los datos del usuario (\(Q\))". Si NO envías el token (\(P = 0\)), el servidor no ha roto su promesa sin importar qué haga, por lo tanto el contrato no ha sido violado (\(P \to Q = 1\)). La promesa únicamente se incumple (es falsa) cuando cumples la condición (\(P=1\)) pero el sistema falla en responder (\(Q=0\)).
2. Glosario de Términos y Definiciones
• Proposición Simple: Enunciado atómico indivisible con valor de verdad (ej. \(P\): 'El puerto 80 está abierto').
• Proposición Compuesta: Unión de dos o más proposiciones mediante conectivos lógicos (ej. \(P \land Q\)).
• Condicional (\(P \to Q\)): "Si \(P\) entonces \(Q\)". Falsa únicamente cuando el antecedente \(P\) es verdadero y el consecuente \(Q\) es falso.
• Bicondicional (\(P \leftrightarrow Q\)): "\(P\) si y solo si \(Q\)". Verdadera cuando ambas proposiciones comparten el mismo valor de verdad.
• Modus Ponens (Regla de Inferencia): Si \(P \to Q\) es verdadero y se afirma la premisa \(P\), se concluye válidamente \(Q\) (\(P \to Q, P \vdash Q\)).
• Modus Tollens (Regla de Inferencia): Si \(P \to Q\) es verdadero y el consecuente es negado (\(\neg Q\)), se concluye \(\neg P\) (\(P \to Q, \neg Q \vdash \neg P\)).
• Leyes de De Morgan: \(\neg(P \land Q) \equiv \neg P \lor \neg Q\) y \(\neg(P \lor Q) \equiv \neg P \land \neg Q\). Fundamentales para refactorizar sentencias condicionales booleanas complejas.
• Ley de Doble Negación e Idempotencia: \(\neg(\neg P) \equiv P\); \(P \land P \equiv P\); \(P \lor P \equiv P\).

Ejemplo 1 Demostración de Equivalencia: \((P \to Q) \equiv (\neg P \lor Q)\)

Construimos la tabla de verdad columna por columna para verificar que ambas expresiones son semánticamente indistinguibles:

\(P\) \(Q\) \(\neg P\) \(P \to Q\) \(\neg P \lor Q\) \((P \to Q) \leftrightarrow (\neg P \lor Q)\)

1 0 0 0 0 1

Evaluando para (1,1): 1=1. Para (1,0): 0=0. Para (0,1): 1=1. Para (0,0): 1=1.
Conclusión: Ambas columnas son idénticas en todas las filas y su bicondicional es una Tautología absoluta, demostrando la equivalencia lógica.

Ejemplo 2 Aplicación Práctica de Inferencia en Diagnóstico de Servidores

Escenario: Un sistema de monitoreo en la nube tiene programadas las siguientes premisas:

  • Premisa 1 (\(P \to Q\)): Si la memoria RAM supera el 95% (\(P\)), se activa el autoescalado de réplicas (\(Q\)).
  • Premisa 2 (\(P\)): El sensor reporta que la memoria RAM superó el 95%.

Aplicando Modus Ponens: De \((P \to Q)\) y \(P\), el motor de inferencias concluye matemáticamente \(Q\): "Se activa el autoescalado de réplicas" con total certeza lógica.

Variante Modus Tollens: Supongamos que sabemos \((P \to Q)\), pero el administrador observa que NO se activó el autoescalado (\(\neg Q\)). Aplicando Modus Tollens (\(P \to Q, \neg Q \vdash \neg P\)), podemos concluir de forma infalible que "La memoria RAM no superó el 95%" (\(\neg P\)).

3.2

Lógica de Predicados y Cuantificadores

1. Explicación Teórica y Conceptual

La lógica proposicional es insuficiente para analizar afirmaciones con estructura interna como "todos los enteros pares son divisibles entre 2". La Lógica de Predicados (o de primer orden) resuelve esta limitación introduciendo sujetos (variables/constantes) y predicados (propiedades o relaciones atribuidas a los sujetos) sobre un dominio de discurso \(D\).

Analogía Computacional (Arrays y Bases de Datos): Piensa en un predicado \(P(x)\) como una función booleana function esAdmin(usuario) { return usuario.rol === 'admin'; }.
  • Universal (\(\forall x\)): Equivale a usuarios.every(u => esAdmin(u)) en JavaScript o NOT EXISTS (SELECT * FROM Users WHERE rol != 'admin') en SQL. Basta un usuario regular para que sea false.
  • Existencial (\(\exists x\)): Equivale a usuarios.some(u => esAdmin(u)) o EXISTS (SELECT * FROM Users WHERE rol = 'admin'). Basta encontrar uno solo para que sea true.

El comportamiento de la negación en cuantificadores obedece a las Leyes de De Morgan Generalizadas:

  • \(\neg(\forall x P(x)) \equiv \exists x \neg P(x)\): Negar que "todos los servidores están en línea" equivale a afirmar que "existe al menos un servidor caído".
  • \(\neg(\exists x P(x)) \equiv \forall x \neg P(x)\): Negar que "existe un archivo infectado" equivale a afirmar que "todos los archivos están libres de infección".
2. Glosario de Términos y Definiciones
• Dominio de Discurso (\(D\)): Conjunto exacto de todos los valores posibles que pueden sustituir a las variables (ej. enteros \(\mathbb{Z}\), registros de una tabla SQL).
• Predicado \(P(x)\): Función que mapea elementos de \(D\) a \(\{0, 1\}\). No es proposición hasta instanciar \(x\) o cuantificarlo.
• Cuantificador Universal (\(\forall x\)): Para todo \(x \in D\), \(P(x)\) es verdadero. Se refuta con un único contraejemplo.
• Cuantificador Existencial (\(\exists x\)): Existe al menos un \(x \in D\) tal que \(P(x)\) es verdadero. Se refuta demostrando que ningún elemento lo cumple.
• Variable Libre vs Ligada: Una variable \(x\) está ligada si está bajo el alcance de un cuantificador (\(\forall x\) ó \(\exists x\)); de lo contrario, es libre.
• Cuantificadores Anidados: Expresiones como \(\forall x \exists y (x + y = 0)\) donde el orden de los cuantificadores altera críticamente el significado.

Ejemplo 1 Negación Formal de Enunciados en Software

Problema: Negar formalmente la proposición: "Todos los programas tienen errores".

1. Formalización: \(\forall x (P(x) \to E(x))\), donde \(P(x)\): "\(x\) es un programa" y \(E(x)\): "\(x\) tiene errores".

2. Aplicando negación: \(\neg[\forall x (P(x) \to E(x))] \equiv \exists x \neg(P(x) \to E(x))\).

3. Equivalencia del condicional (\(\neg(A \to B) \equiv A \land \neg B\)): \(\exists x (P(x) \land \neg E(x))\).

Traducción al lenguaje natural: "Existe al menos un programa que no tiene errores". (Falso el mito de que negar "todos tienen errores" sería "ninguno tiene errores").

Ejemplo 2 Especificación Formal de Restricciones de Red

Problema: Traducir a lógica de predicados el requisito de ciberseguridad: "Para cada servidor web existe un firewall que bloquea puertos no autorizados".

• Dominio: Servidores \(S\) y Firewalls \(F\).

• Predicados: \(Web(s)\): "\(s\) es servidor web", \(Protege(f, s)\): "el firewall \(f\) filtra y protege a \(s\)".

• Formalización: \(\forall s \, (Web(s) \to \exists f \, (Firewall(f) \land Protege(f, s)))\).

Nota didáctica: Observa la posición de los cuantificadores: \(\forall s \exists f\) indica que cada servidor puede tener su propio firewall dedicado. En contraste, \(\exists f \forall s\) significaría que un único firewall centralizado protege a todos los servidores de la red.

3.3

Álgebra Declarativa y Programación Lógica

1. Explicación Teórica y Conceptual

El Álgebra Declarativa fundamenta el paradigma de Programación Lógica. A diferencia del paradigma imperativo tradicional (C, Java, Python) donde el programador le dicta a la máquina "cómo calcular la solución paso por paso" mediante ciclos y mutaciones de estado, en la programación lógica se le describe "qué relaciones y axiomas lógicos son verdaderos", delegando la búsqueda de soluciones a un motor de inferencia automatizado.

Comparativa Práctica: Imperativo vs Declarativo
Enfoque Imperativo (¿Cómo?): for (User u : list) {
  if (u.age >= 18 && u.active)
    result.add(u);
}
Enfoque Declarativo (¿Qué?): SELECT * FROM Users
WHERE age >= 18 AND active = 1;
/* O en Prolog: */
habilitado(U) :- edad(U, E), E >= 18, activo(U).

El estándar formal de la programación lógica (representado por Prolog y los motores Datalog para grafos de conocimiento) descansa sobre las Cláusulas de Horn. Un programa se compone de:

  • Hechos (Facts): Aseveraciones incondicionales de verdad (ej. conexion(servidor1, switchA).).
  • Reglas (Rules): Implicaciones lógicas de la forma "Cabeza :- Cuerpo" (\(H \leftarrow B_1 \land B_2\)), significando que la Cabeza es verdadera siempre que todas las metas del Cuerpo sean satisfechas.
  • Consultas (Queries / Goals): Preguntas que el usuario hace al sistema (ej. ?- admin(juan).). El motor ejecuta unificación y backtracking para encontrar las variables que satisfacen la meta.
2. Glosario de Términos y Definiciones
• Cláusula de Horn: Disyunción de literales con a lo más un literal positivo (\(B \lor \neg A_1 \lor \dots \lor \neg A_n \equiv B \leftarrow A_1 \land \dots \land A_n\)).
• Hecho (Fact): Cláusula de Horn sin cuerpo negativo (\(B \leftarrow \text{true}\)). Representa verdades directas en la base del conocimiento.
• Regla (Rule): Relación condicional donde la cabeza se deduce si todos los predicados del cuerpo son demostrables.
• Unificación: Algoritmo algebraico que encuentra sustituciones de variables idénticas para hacer que dos expresiones coincidan sintácticamente.
• Backtracking (Retroceso): Estrategia del motor de resolución que regresa sobre caminos previos alternativos cuando una rama de deducción falla.
• Principio de Resolución de Robinson: Regla de inferencia formal refutacional utilizada por los demostradores de teoremas para deducir contradicciones.

Problema: Modelar la alcanzabilidad entre routers en una topología de red.

3.4

Inducción Matemática y Demostraciones

1. Explicación Teórica y Conceptual

La Inducción Matemática es el método por excelencia en ciencias de la computación para demostrar que una propiedad \(P(n)\) se cumple para infinitos números naturales (\(n \in \mathbb{N}\)). No debe confundirse con la inducción empírica de las ciencias naturales (donde observar 100 cisnes blancos no garantiza que el próximo no sea negro); la inducción matemática es un método deductivo riguroso e infalible fundamentado en el Principio del Buen Orden.

Conexión Directa con la Computación (Recursión): La inducción matemática es el "espejo teórico" de una función recursiva:
  • Caso Base: Es la condición de parada del algoritmo recursivo (evita un StackOverflowError).
  • Paso Inductivo: Garantiza que si la llamada recursiva para tamaño \(k\) devuelve el resultado correcto, la combinación con el nuevo elemento produce la respuesta correcta para tamaño \(k+1\).

El esquema estándar de una demostración inductiva simple consta de 3 fases obligatorias:

  1. Paso Base: Demostrar directamente que \(P(n_0)\) es verdadero para el valor inicial (usualmente \(n_0 = 0\) ó \(n_0 = 1\)).
  2. Hipótesis de Inducción (HI): Asumir como hipótesis provisional que la proposición es cierta para un entero arbitrario \(k \ge n_0\): se asume que \(P(k)\) es verdad.
  3. Paso Inductivo: Demostrar formalmente que, apoyándonos en la verdad de \(P(k)\), se deduce necesariamente la veracidad de \(P(k+1)\). Si esto se logra, la propiedad queda demostrada para todo \(n \ge n_0\).
2. Glosario de Términos y Definiciones
• Paso Base (\(n_0\)): Demostración aritmética directa de que el enunciado es válido en su punto de partida.
• Hipótesis Inductiva: La premisa \(P(k)\) que se utiliza como herramienta algebraica en el paso siguiente.
• Paso Inductivo (\(P(k) \to P(k+1)\)): Núcleo de la prueba; demuestra que la veracidad se transfiere al sucesor.
• Inducción Fuerte o Completa: Variante donde para probar \(P(k+1)\) se asume cierta la propiedad para todos los casos anteriores \(P(1), P(2), \dots, P(k)\). Indispensable para teoremas de árboles binarios.
• Principio del Buen Orden: Axioma de los números naturales que establece que todo subconjunto no vacío de \(\mathbb{N}\) contiene un elemento mínimo.
• Demostración por Contradicción (Reductio ad absurdum): Método alternativo donde se asume \(\neg P\) y se deriva una incongruencia lógica.

Ejemplo 1 Suma Aritmética de Gauss (Análisis de Complejidad)

Problema: Demostrar por inducción matemática que \(1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2}\) para todo \(n \ge 1\).

1. Paso Base (\(n=1\)):
Lado izquierdo: \(1\).
Lado derecho: \(\frac{1(1+1)}{2} = \frac{2}{2} = 1\).
Como \(1 = 1\), el caso base se cumple con éxito.

2. Hipótesis Inductiva:
Asumimos que para un entero \(k \ge 1\) se cumple:
\(1 + 2 + \dots + k = \frac{k(k+1)}{2}\).

3. Paso Inductivo (\(n = k+1\)):
Debemos probar que:
\(1 + 2 + \dots + k + (k+1) = \frac{(k+1)((k+1)+1)}{2} = \frac{(k+1)(k+2)}{2}\).
Sustituimos la hipótesis de inducción en los primeros \(k\) términos:
\([1 + 2 + \dots + k] + (k+1) = \frac{k(k+1)}{2} + (k+1)\).
Sacamos factor común \((k+1)\):
\(= (k+1) \left( \frac{k}{2} + 1 \right) = (k+1) \left( \frac{k+2}{2} \right) = \frac{(k+1)(k+2)}{2}\).

El lado izquierdo es idéntico al derecho. Por el principio de inducción matemática, queda demostrado para todo \(n \ge 1\).

Ejemplo 2 Nodos en Árboles Binarios / Direccionamiento de Bits

Problema: Demostrar que la suma de potencias de 2 cumple \(1 + 2 + 4 + \dots + 2^n = 2^{n+1} - 1\) para todo \(n \ge 0\).

1. Base (\(n=0\)): \(2^0 = 1\); \(2^{0+1} - 1 = 2^1 - 1 = 1\) (Cumple).

2. Hipótesis (\(n=k\)): \(1 + 2 + \dots + 2^k = 2^{k+1} - 1\).

3. Paso (\(n=k+1\)):
\((1 + 2 + \dots + 2^k) + 2^{k+1} = (2^{k+1} - 1) + 2^{k+1} = 2 \cdot 2^{k+1} - 1 = 2^{k+2} - 1\).
Expresión que coincide exactamente con \(2^{(k+1)+1} - 1\).

Demostrado: Un árbol binario completo de altura \(n\) tiene exactamente \(2^{n+1}-1\) nodos en total.

3.5

Aplicaciones de la Lógica en la Computación

1. Explicación Teórica y Conceptual

La lógica matemática es el lenguaje formal detrás de la ingeniería de software moderna, la arquitectura de procesadores y los sistemas de alta confiabilidad. Lejos de ser solo teoría abstracta, opera activamente en:

Optimización en Compiladores: Los compiladores (GCC, Clang, JVM JIT) analizan expresiones booleanas complejas en el AST y aplican leyes algebraicas para eliminar ramas muertas y reducir saltos condicionales en lenguaje ensamblador.
Verificación Formal y Lógica de Hoare: En software de aviónica (NASA, Airbus) y contratos inteligentes (Ethereum), se usa la Lógica de Hoare \(\{P\} \, C \, \{Q\}\) para probar matemáticamente que si se cumple la precondición \(P\), el comando \(C\) terminará garantizando la postcondición \(Q\) sin bugs ni desbordamientos de buffer.
Optimizadores de Consultas SQL: El motor de base de datos (PostgreSQL, MySQL) traduce las cláusulas WHERE a lógica proposicional y las reorganiza (Pushdown Predicates) para filtrar tablas antes de realizar joins masivos.
Evaluación de Cortocircuito: En if (ptr != null && ptr.val > 0), la semántica de cortocircuito garantiza que si la primera proposición es falsa, la segunda jamás se evalúa, evitando un NullPointerException mortal.
2. Glosario de Términos y Definiciones
• Verificación Formal: Demostración matemática rigurosa de que un programa cumple sus especificaciones sin errores de ejecución.
• Cortocircuito Lógico: Optimización en lenguajes donde A && B no evalúa B si A es falso, y A || B no evalúa B si A es verdadero.
• Invariante de Bucle: Condición lógica \(I\) que se mantiene verdadera antes de iniciar el ciclo y después de cada iteración, garantizando la correctitud al finalizar.
• Tripleta de Hoare (\(\{P\} C \{Q\}\)): Formalismo lógico que certifica que el código \(C\) transforma un estado válido \(P\) en un estado final deseado \(Q\).
• Refactorización Booleana: Reescritura de expresiones en condicionales para reducir ciclos de reloj y mejorar legibilidad mediante álgebra proposicional.
• Problema SAT (Satisfacibilidad Booleana): Problema NP-completo fundamental en computación teórica para determinar si existe una asignación que haga verdadera una fórmula dada.

Ejemplo 1 Simplificación de Código Redundante en Condicionales

Problema: Un programador novato escribió la siguiente condición en Java / C++: if (x > 0 || (x <= 0 && y > 5)). Demostrar algebraicamente si puede optimizarse.

1. Definimos las proposiciones atómicas: \(P: (x > 0)\), \(Q: (y > 5)\). Por lo tanto \(\neg P: (x \le 0)\).

2. Expresión lógica: \(P \lor (\neg P \land Q)\).

3. Aplicamos la Ley Distributiva de la disyunción sobre la conjunción:
\((P \lor \neg P) \land (P \lor Q)\).

4. Ley del Tercero Excluido (\(P \lor \neg P \equiv 1\) / True):
\(1 \land (P \lor Q)\).

5. Ley de Identidad (\(1 \land A \equiv A\)):
\(P \lor Q\).

Código refactorizado idéntico: if (x > 0 || y > 5). Eliminamos una comparación innecesaria en CPU y mejoramos la legibilidad del código.

Ejemplo 2 Verificación de Correctitud mediante Invariante de Bucle

Problema: Demostrar la correctitud del algoritmo para encontrar la suma de un array A[0..n-1]:

int s = 0; int i = 0;

while (i < n) { s += A[i]; i++; }

Invariante propuesto \(I\): Al inicio de cada iteración, \(s = \sum_{j=0}^{i-1} A[j]\).

• Inicialización: Antes del bucle (\(i = 0\)), \(s = 0\) (suma de 0 elementos es vacía = 0). \(I\) es verdadero.
• Mantenimiento: Si \(s\) contiene la suma hasta \(i-1\), tras sumar \(A[i]\) e incrementar \(i\), \(s\) contendrá la suma hasta el nuevo \(i-1\). El invariante se preserva.
• Terminación: El bucle termina cuando \(i = n\). Sustituyendo en \(I\): \(s = \sum_{j=0}^{n-1} A[j]\), demostrando matemáticamente que el programa calcula la suma correcta sin fallas.
