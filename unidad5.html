Unidad 5: Análisis Léxico (Scanner)

Duración: 15 Horas (15 Horas) • Nivel Avanzado • Docente: Cruz Enrique García

El Análisis Léxico (también llamado escáner o scanner) constituye la primera fase del front-end de un compilador. Su tarea fundamental consiste en leer la secuencia de caracteres del programa fuente de izquierda a derecha, agruparlos en unidades con significado lógico llamadas componentes léxicos (tokens) y suministrarlos al analizador sintáctico a petición de este.

Competencia Específica

Construir un analizador léxico a partir de un lenguaje de programación o mediante herramientas generadoras (Flex, Lex, JFlex, JavaCC, PLY), identificando patrones, gestionando la tabla de símbolos y manejando errores léxicos.

5.1 Funciones del Analizador Léxico

La función primordial del analizador léxico es transformar un flujo continuo de caracteres no estructurado en una corriente estructurada de tokens. Sin embargo, realiza múltiples tareas complementarias esenciales para la eficiencia del compilador:

Lectura y Agrupamiento de Caracteres

Lee los caracteres del flujo de entrada y los agrupa en lexemas que coinciden con los patrones definidos para el lenguaje.

Eliminación de Elementos No Significativos

Filtra y descarta espacios en blanco, tabulaciones, saltos de línea y comentarios del código fuente sin sobrecargar al analizador sintáctico.

Interacción con la Tabla de Símbolos

Detecta nuevos identificadores, los inserta en la tabla de símbolos o recupera su información de atributos si ya fueron declarados.

Control de Ubicación y Detección de Errores

Mantiene contadores de número de línea y columna para emitir mensajes de error precisos referenciando la posición exacta del error.

Código Fuente
total = suma + 10;

getNextToken()

5.2 Componentes Léxicos, Patrones y Lexemas

Es indispensable distinguir con precisión técnica entre estos tres conceptos fundamentales:

Token

Categoría o símbolo abstracto que representa una unidad de información sintáctica (ej. ID, NUMERO, IF, OP_ASIG).

Lexema

La secuencia concreta de caracteres en el código fuente que coincide con el patrón de un token (ej. radio, 3.14159, if, =).

Patrón

La regla formal de descripción (expresión regular) que deben satisfacer los caracteres para formar un token específico.

Token (Nombre) Patrón Informal / ER Lexemas de Ejemplo
IF if if
ID letra (letra | digito | _)* contador, valor_1, temp
NUM_INT digito+ 0, 42, 1024
NUM_REAL digito+ . digito+ ([eE][+-]? digito+)? 3.14, 0.05, 1.2e-4
OP_REL < | <= | == | >= | > | != <=, !=, ==

5.3 Creación y Gestión de la Tabla de Tokens

La Tabla de Tokens almacena la secuencia de pares <Token, Atributo> producida por el analizador léxico. Los identificadores se vinculan con una entrada en la Tabla de Símbolos, donde se concentran sus propiedades (tipo de dato, dirección de memoria, ámbito de visibilidad, etc.).

Estructura de Token en C++ / Java 
enum TokenType {
    TOKEN_IF, TOKEN_ELSE, TOKEN_WHILE,
    TOKEN_ID, TOKEN_INT_LITERAL, TOKEN_FLOAT_LITERAL,
    TOKEN_ASSIGN, TOKEN_PLUS, TOKEN_MINUS,
    TOKEN_SEMICOLON, TOKEN_EOF, TOKEN_ERROR
};

struct Token {
    TokenType type;
    std::string lexeme;
    int line;
    int column;
    // Puntero o índice hacia la tabla de símbolos para identificadores
    int symbol_table_index; 
};

Tip de Eficiencia: Búfer Doble (Double Buffering)

Para evitar llamadas lentas al sistema operativo carácter por carácter, los escáneres profesionales utilizan un búfer doble circular con dos punteros: inicio_lexema y puntero_hacia_adelante, cargando bloques de 4096 bytes con centinelas de fin de bloque.

5.4 Errores Léxicos y Estrategias de Recuperación

Un error léxico ocurre cuando ningún prefijo del flujo restante de caracteres coincide con el patrón de algún token válido. Ejemplos clásicos:

  • Carácter no reconocido: Símbolos extraños en el lenguaje (ej. @, $, ~ cuando no están contemplados en el alfabeto).
  • Cadena o comentario sin cerrar: Llegar a fin de archivo (EOF) con una comilla o delimitador abierto.
  • Constante numérica mal formada: Múltiples puntos decimales (ej. 12.34.56) o exponente sin dígitos.

Estrategias de Recuperación

La estrategia más común es el Modo Pánico: descartar caracteres hasta que el analizador pueda encontrar un prefijo que comience un nuevo token válido, emitiendo un reporte con número de línea y columna.

5.5 Generadores Automáticos (Flex, JFlex, PLY)

En lugar de escribir a mano una máquina de estados para cada token, se emplean generadores automáticos de escáneres. Estas herramientas reciben una especificación de expresiones regulares y acciones en código huésped, aplicando internamente el Algoritmo de Thompson y la Construcción de Subconjuntos para producir código en C, Java o Python.

Especificación JFlex (Java) - scanner.flex 
%%
%class MiniScanner
%type Token
%line
%column

/* Expresiones Regulares */
LETRA   = [a-zA-Z_]
DIGITO  = [0-9]
ID      = {LETRA}({LETRA}|{DIGITO})*
NUMERO  = {DIGITO}+
BLANCO  = [ \t\r\n]+

%%

/* Reglas y Acciones */
"if"            { return new Token(TokenType.IF, yytext(), yyline, yycolumn); }
"else"          { return new Token(TokenType.ELSE, yytext(), yyline, yycolumn); }
"while"         { return new Token(TokenType.WHILE, yytext(), yyline, yycolumn); }
{NUMERO}        { return new Token(TokenType.NUM, yytext(), yyline, yycolumn); }
{ID}            { return new Token(TokenType.ID, yytext(), yyline, yycolumn); }
"="             { return new Token(TokenType.ASSIGN, yytext(), yyline, yycolumn); }
"+"             { return new Token(TokenType.PLUS, yytext(), yyline, yycolumn); }
";"             { return new Token(TokenType.SEMI, yytext(), yyline, yycolumn); }
{BLANCO}        { /* Ignorar espacios */ }
.               { return new Token(TokenType.ERROR, yytext(), yyline, yycolumn); }
