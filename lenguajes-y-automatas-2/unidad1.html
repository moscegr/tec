Fase de Análisis Semántico (SCD-1016)

El Análisis Semántico es la tercera fase de un compilador. Su misión es verificar que el árbol sintáctico generado cumpla con las reglas lógicas y de tipado del lenguaje de programación (comprobación de tipos, compatibilidad de operandos, existencia de variables y ámbito). En esta unidad, todo el trabajo se realiza mediante análisis manual riguroso, construcción de árboles de expresiones, evaluación en pilas semánticas verticales (IDR y RID) y tablas de símbolos y direcciones.

1.1

Árboles de Expresiones y Representaciones Equivalentes

1. Explicación Teórica y Conceptual

Un árbol es una estructura jerárquica no lineal aplicada sobre una colección de elementos llamados nodos, donde existe un nodo distinguido denominado raíz. Formalmente, un árbol de tipo \(T\) se define recursivamente como la concatenación de un elemento tipo \(T\) junto con un conjunto finito de árboles disjuntos denominados subárboles.

Un Árbol de Expresión Sintáctica (A.A.S. o AST) representa la estructura jerárquica de una operación: las hojas corresponden a los operandos (constantes numéricas o identificadores de variables) y los nodos interiores corresponden a los operadores (\(+, -, *, /, \wedge, =\)).

Gráficamente, una misma estructura arbórea puede representarse de 5 formas completamente equivalentes:

  1. Diagramas de Venn: Conjuntos y subconjuntos anidados espacialmente.
  2. Anidación de Paréntesis: Notación prefija agrupada (ej. (A (B (D(I), E, F(J, K)), C(G, H(L))))).
  3. Notación Decimal de Dewey: Numeración jerárquica por niveles (ej. 1. A, 1.1.B, 1.1.1.D, 1.1.1.1.I...).
  4. Notación Indentada: Sangrías tabulares como en código estructurado (YAML / Python).
  5. Grafo Jerárquico: Nodos circulares unidos por aristas dirigidas (raíz en la parte superior).
2. Glosario de Términos y Definiciones
• Raíz: Nodo único en el nivel superior que no posee nodo padre.
• Hijo / Descendiente directo: Nodo apuntado directamente por un nodo padre.
• Padre / Antecesor directo: Nodo que apunta a sus nodos hijos.
• Hermanos: Nodos que descienden directamente del mismo padre.
• Hoja / Nodo terminal: Nodo que no tiene hijos (\(\text{grado} = 0\)).
• Nodo interior: Todo nodo que no es raíz ni hoja.
• Grado de un nodo: Número de hijos directos que posee. Grado del árbol: El máximo grado entre todos los nodos.
• Altura del árbol: Número total de niveles desde la raíz hasta la hoja más profunda.
3. Ejemplo con Diagrama Vectorial de las 5 Representaciones
Árbol Sintáctico de la Expresión: (A + B) * (C - D)
Preorden (RID):
* + A B - C D
Inorden (IRD):
A + B * C - D
Posorden (IDR):
A B + C D - *
4. Ejercicio Guiado Paso a Paso

Construcción y Recorridos para la Expresión: \(Z = (A * B) + (C / D) \wedge 2\)

1. Identificar operador de menor precedencia: La asignación \(=\) es la raíz principal.
2. Hijo izquierdo de \(=\): La variable receptora \(Z\).
3. Hijo derecho de \(=\): El operador de suma \(+\), cuyos operandos son el subárbol \(A * B\) a la izquierda y \((C / D) \wedge 2\) a la derecha.
4. Subárbol derecho de \(+\): Raíz \(\wedge\), hijo izquierdo el subárbol \(C / D\) y derecho la constante 2.

• Preorden (RID): = Z + * A B ^ / C D 2

• Inorden (IRD): Z = A * B + C / D ^ 2

• Posorden (IDR): Z A B * C D / 2 ^ + =

• Notación de Dewey: 1.=, 1.1.Z, 1.2.+, 1.2.1.*, 1.2.1.1.A, 1.2.1.2.B, 1.2.2.^, 1.2.2.1./, 1.2.2.1.1.C, 1.2.2.1.2.D, 1.2.2.2.2

1.2

Acciones Semánticas de un Analizador Sintáctico

1. Explicación Teórica y Conceptual

Las acciones semánticas son fragmentos de lógica procedimental insertados directamente dentro de las producciones de una Gramática Libre de Contexto (GLC). Mientras el analizador sintáctico reconoce la estructura gramatical del programa, las acciones semánticas se ejecutan al momento de realizar una reducción sintáctica para calcular tipos de datos, evaluar constantes numéricas, verificar ámbitos e insertar identificadores en la tabla de símbolos.

Se manejan dos tipos de atributos semánticos:

  • • Atributos Sintetizados (\(S\)-atribuidos): El valor del nodo padre se calcula exclusivamente a partir de los valores de sus nodos hijos. La evaluación se realiza de abajo hacia arriba (bottom-up).
  • • Atributos Heredados (\(L\)-atribuidos): El valor del nodo depende de los atributos de sus nodos hermanos a la izquierda o de su nodo padre. La evaluación fluye de arriba hacia abajo o de izquierda a derecha.
2. Glosario de Términos
DDS (Definición Dirigida por Sintaxis): Especificación declarativa que asocia atributos y reglas a producciones.
Grafo de Dependencia: Dígrafo que define el orden topológico válido para evaluar atributos.
3. Esquema de Evaluación S-Atribuida

// Gramática Atribuida para una Calculadora:

E ➔ E₁ + T   { E.val = E₁.val + T.val; E.tipo = verificarTipo(E₁.tipo, T.tipo); }

E ➔ T        { E.val = T.val; E.tipo = T.tipo; }

T ➔ T₁ * F   { T.val = T₁.val * F.val; }

F ➔ NUM      { F.val = NUM.lexval; F.tipo = 'int'; }

4. Ejercicio Guiado

Para la entrada 3 * 5 + 4: 1) F(3).val = 3 ➔ T(3).val = 3.
2) F(5).val = 5 ➔ Reducción T ➔ T * F calcula T.val = 3 * 5 = 15.
3) E.val = 15. Se lee 4 ➔ F(4).val = 4 ➔ T(4).val = 4.
4) Reducción E ➔ E + T calcula E.val = 15 + 4 = 19.

5. Ejercicio de Práctica (Firmas 40%)

Diseña las reglas semánticas para convertir un número binario a decimal mediante atributos sintetizados para la gramática: \(B \to B_1 D \mid D\), con \(D \to 0 \mid 1\). Pista: \(B.val = B_1.val * 2 + D.val\).

1.3

Comprobaciones de Tipos en Expresiones

1. Explicación Teórica

El Sistema de Tipos de un lenguaje define el conjunto de tipos básicos (int, float, char, boolean), constructores de tipos (arreglos, registros/estructuras, punteros, funciones) y las reglas de compatibilidad.

La comprobación estática de tipos garantiza que:

  • • Equivalencia de Tipos: En asignaciones \(V = E\), el tipo de \(E\) debe ser compatible con el tipo de \(V\).
  • • Sobrecarga de Operadores: El operador \(+\) significa suma entera si los operandos son int, suma flotante si son float, o concatenación si son string.
  • • Coerción de Tipos (Conversión Implícita): Promoción automática sin pérdida de precisión (ej. int + float ➔ float + float ➔ float).

1.4

Pila Semántica en un Analizador Sintáctico (Representación Vertical IDR y RID)

1. Fundamentación y Criterios de Evaluación

La Pila Semántica es una estructura de datos LIFO (Last In, First Out) utilizada por el analizador semántico para almacenar operandos, tipos de datos, direcciones y operadores durante el recorrido del Árbol de Análisis Sintáctico (A.A.S.).

Una vez construido el A.A.S., se apilan todos los elementos según dos posibles métodos de recorrido, aplicando reglas exactas de reducción:

A) Pila con Recorrido IDR (Posorden)

Criterio de Evaluación: SiVaVa (Signo - Valor - Valor)

Para evaluar, se busca en la pila la terna de 1 Operador / Signo seguido de 2 Operandos / Valores consecutivos. Se extraen, se calcula la operación y el resultado se reinserta en la pila. Se itera recursivamente hasta dejar el resultado final en el TOS.

B) Pila con Recorrido RID (Preorden)

Criterio de Evaluación: VaVaSi (Valor - Valor - Signo)

Para evaluar, se busca en la pila la terna de 2 Operandos / Valores seguidos de 1 Operador / Signo. Se extraen, se ejecuta la operación y se actualiza la pila recursivamente.

1.5

Esquema de Traducción Dirigido por la Sintaxis

1. Explicación Teórica

Un Esquema de Traducción Dirigido por la Sintaxis (ETDS) es una gramática libre de contexto en la que se intercalan acciones semánticas dentro del lado derecho de las producciones gramaticales. A diferencia de una DDS pura, el ETDS define explícitamente el momento y orden temporal en que cada acción debe ejecutarse durante el recorrido del árbol sintáctico.

3. Ejemplo de ETDS para Traducción de Infijo a Postfijo

// Producciones con acciones semánticas intercaladas:

E ➔ T R

R ➔ + T { print('+'); } R₁

R ➔ ε

T ➔ num { print(num.val); }

5. Ejercicio de Práctica (Firmas 40%)

Diseña un esquema de traducción que convierta expresiones con operadores * y + en notación prefija. Pista: Las acciones print se colocan antes de los no terminales.

1.6

Generación de la Tabla de Símbolos y Tabla de Direcciones

1. Explicación Teórica

La Tabla de Símbolos almacena los metadatos de cada identificador declarado en el código fuente: nombre del lexema, categoría (variable, función, parámetro), tipo de dato, ámbito (scope: global o local) y su dirección relativa de memoria (offset).

La Tabla de Direcciones calcula el desplazamiento en bytes en el marco de pila (*stack frame*) según los anchos estándar de tipos: char: 1 byte, int: 4 bytes, float: 4 bytes, double: 8 bytes, arreglo T[N]: N * ancho(T).

1.7

Manejo de Errores Semánticos

1. Explicación Teórica

Un error semántico ocurre cuando un programa es sintácticamente correcto según la gramática, pero viola las reglas de significado, tipos o ámbito del lenguaje.

Los errores semánticos más comunes son:

  1. Variable no declarada: Intentar usar un identificador que no existe en la tabla de símbolos.
  2. Redeclaración de variable: Declarar dos veces el mismo identificador dentro del mismo ámbito.
  3. Incompatibilidad de tipos: Intentar asignar valores no convertibles (ej. asignar string a int).
  4. Llamada incorrecta a función: Discrepancia en el número o tipos de argumentos pasados respecto a la firma de la función.
  5. Acceso inválido a arreglos: Indexar una variable que no es un arreglo o usar un índice no entero.
3. Registro y Reporte de Errores Semánticos

[ERROR SEMÁNTICO Línea 14, Col 8]: Variable 'total' no ha sido declarada en este ámbito.

[ERROR SEMÁNTICO Línea 22, Col 12]: Incompatibilidad de tipos: No se puede asignar 'string' a la variable entera 'edad'.

[ERROR SEMÁNTICO Línea 30, Col 5]: La función 'calcularPromedio(int, int)' requiere 2 argumentos, se recibieron 3.

5. Ejercicio de Práctica (Firmas 40%)

Dado un programa fuente de 15 líneas con 4 errores semánticos intencionales, elabora el reporte de la fase de análisis semántico indicando línea, tipo de error y regla semántica violada.
