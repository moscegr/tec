Unidad 1: Análisis Semántico y la Pila Semántica

Duración: 20 Horas (Semanas 1-4) • Intermedio - Avanzado • Docente: Cruz Enrique García

El Análisis Semántico es la fase del compilador encargada de verificar que la estructura sintáctica del programa fuente tenga un significado coherente y válido según las reglas del lenguaje. Mientras que el analizador léxico reconoce palabras y el sintáctico verifica la gramática, el analizador semántico comprueba que las operaciones tengan sentido (ej. no sumar una cadena con un booleano, verificar que las variables estén declaradas antes de usarse y calcular tipos de expresiones).

Competencia Específica

Diseñar y construir un analizador semántico mediante el uso de reglas semánticas dirigidas por sintaxis en JFlex y CUP, implementando la comprobación de tipos, la gestión de la tabla de símbolos y la evaluación de expresiones mediante la pila semántica.

1.1 Árboles de Expresiones y Representaciones

Un árbol es una estructura jerárquica homogénea no lineal aplicada sobre una colección de nodos, donde existe un nodo distinguido llamado raíz. Los árboles se definen recursivamente: un elemento raíz conectado a un conjunto finito de subárboles disjuntos.

Raíz Único nodo sin padre (Nivel 1)
Hoja Nodo terminal sin hijos (Grado 0)
Grado Número de hijos directos
Altura Máximo número de niveles

Las 5 Formas de Representación de un Árbol

Diagramas de Venn (Conjuntos Anidados)

Representa la jerarquía mediante recuadros o elipses de inclusión donde los nodos padres contienen a los subárboles hijos.

Anidación de Paréntesis

(A (B (D (I), E, F (J, K)), C (G, H (L))))

Notación Decimal de Dewey

1. A, 1.1.B, 1.1.1.D, 1.1.1.1.I, 1.1.2.E, 1.1.3.F, 1.1.3.1.J, 1.1.3.2.K, 1.2.C, 1.2.1.G, 1.2.2.H, 1.2.2.1.L

Notación Indentada (Jerárquica)

A
  ├── B
  │   ├── D ── I
  │   ├── E
  │   └── F ── J, K
  └── C
      ├── G
      └── H ── L

Notación por Grafo (Árbol Sintáctico)

La representación gráfica tradicional con nodos circulares y aristas dirigidas de arriba hacia abajo.

Recorridos Recursivos de Árboles Binarios

PREORDEN (RID)
  1. Visitar la Raíz
  2. Subárbol Izquierdo
  3. Subárbol Derecho
INORDEN (IRD)
  1. Subárbol Izquierdo
  2. Visitar la Raíz
  3. Subárbol Derecho
POSORDEN (IDR)
  1. Subárbol Izquierdo
  2. Subárbol Derecho
  3. Visitar la Raíz

1.2 - 1.3 Acciones Semánticas y Comprobación de Tipos

Las acciones semánticas son fragmentos de código embebidos dentro de las producciones gramaticales en herramientas como CUP. Se ejecutan durante la reducción sintáctica para evaluar valores, construir nodos del AST y validar reglas de tipo.

Gramática Atribuida en CUP (Java) - Parser.cup 
/* Especificación Semántica en CUP con Comprobación de Tipos */
expr ::= expr:e1 PLUS term:e2
         {: 
            if (e1.type != e2.type) {
                // Coerción implícita de int a float si es compatible
                if (e1.type == Type.INT && e2.type == Type.FLOAT) {
                    RESULT = new ASTNode(Type.FLOAT, "PLUS", new CastNode(e1, Type.FLOAT), e2);
                } else if (e1.type == Type.FLOAT && e2.type == Type.INT) {
                    RESULT = new ASTNode(Type.FLOAT, "PLUS", e1, new CastNode(e2, Type.FLOAT));
                } else {
                    parser.report_semantic_error("Incompatibilidad de tipos en suma: " + e1.type + " + " + e2.type);
                }
            } else {
                RESULT = new ASTNode(e1.type, "PLUS", e1, e2);
            }
         :}
       | term:t {: RESULT = t; :};

Coerción (Casting) Implícito vs Explícito

Cuando los tipos no coinciden exactamente pero son compatibles (ej. sumar int con float), el analizador semántico inserta un nodo de conversión implícita (widening) en el árbol sintáctico sin detener la compilación.

1.4 La Pila Semántica (Evaluación IDR vs RID)

La Pila Semántica es una estructura de datos LIFO (*Last-In, First-Out*) que almacena temporalmente los registros semánticos (operadores y operandos) durante la evaluación del Árbol de Análisis Sintáctico (A.A.S.).

Recorrido IDR (Posfijo)

Criterio SiVaVa

Regla SiVaVa: Se busca la terna Signo - Valor - Valor (1 Operador seguido de 2 Operandos hacia el fondo). Se calcula el resultado, se sustituyen los 3 elementos por el nuevo valor y se repite recursivamente hasta vaciar la pila.

TOP ──► [ + ] [ 3 ] [ * ] [ 4 ] [ + ] [ 2 ] [ 1 ] ◄── Fondo

Recorrido RID (Prefijo)

Criterio VaVaSi

Regla VaVaSi: Se busca la terna Valor - Valor - Signo (2 Operandos seguidos de 1 Operador). Se aplica el operador sobre los dos valores inmediatos, actualizando la pila.

TOP ──► [ 3 ] [ 4 ] [ 2 ] [ 1 ] [ + ] [ * ] [ + ] ◄── Fondo

1.6 - 1.7 Tabla de Símbolos y Manejo de Errores

La Tabla de Símbolos mantiene el entorno de ejecución por bloques anidados (*scopes*). Cada entrada registra: nombre, tipo, tamaño en bytes, desplazamiento (*offset* en el stack) y visibilidad.

Variable no declarada

Uso de un identificador sin entrada en la tabla del scope actual ni en sus ancestros.

Doble declaración

Declarar dos identificadores con el mismo nombre dentro del mismo bloque léxico.

Tipo incompatible

Asignar una estructura compleja a un escalar o aplicar operadores inválidos.
