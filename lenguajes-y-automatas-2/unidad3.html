3.1

Introducción a CUP y Gramáticas LALR(1)

1. Explicación Teórica y Conceptual

CUP (Constructor of Useful Parsers) es un generador de analizadores sintácticos para Java basado en el algoritmo LALR(1) (Look-Ahead Left-to-right Rightmost derivation). CUP toma un archivo de especificación sintáctica con extensión .cup y genera automáticamente dos clases Java fundamentales:

  • • sym.java: Contiene constantes numéricas enteras que representan a todos los símbolos terminales (tokens) del lenguaje (ej. public static final int MAS = 5;).
  • • parser.java: Es el autómata de pila LALR(1) que implementa el método parse() y solicita tokens al escáner léxico.
2. Estructura de un Archivo .cup
1. Declaraciones: package e import java_cup.runtime.*;
2. Código Embebido: parser code {: ... :} para métodos personalizados.
3. Símbolos: terminal [Tipo] NOM; y non terminal [Tipo] nom;
4. Precedencias: precedence left MAS, MENOS;
5. Producciones: expr ::= expr:e1 MAS expr:e2 {: RESULT = e1 + e2; :};
Symbol: Objeto con sym (ID del token), left (línea), right (columna) y value (lexema).
3. Diagrama: Flujo de Generación de Clases con CUP
Pipeline de Compilación CUP ➔ Java
4. Ejercicio Guiado: Primer Archivo Parser.cup Básico 
package compilador;
import java_cup.runtime.*;

parser code {:
    public void report_error(String message, Object info) {
        System.err.println("Error sintáctico: " + message);
    }
:};

/* Terminales devueltos por el escáner */
terminal MAS, MENOS, POR, DIV, PAREN_IZQ, PAREN_DER, PUNTO_COMA;
terminal Integer NUMERO;

/* No terminales */
non terminal expr_lista, expr_pt;
non terminal Integer expr;

/* Reglas gramaticales */
expr_lista ::= expr_lista expr_pt
             | expr_pt;

expr_pt    ::= expr:e PUNTO_COMA {: System.out.println("Resultado = " + e); :};

expr       ::= expr:e1 MAS expr:e2   {: RESULT = e1 + e2; :}
             | expr:e1 POR expr:e2   {: RESULT = e1 * e2; :}
             | PAREN_IZQ expr:e PAREN_DER {: RESULT = e; :}
             | NUMERO:n              {: RESULT = n; :};

3.2

Precedencia, Asociatividad y Conflictos Shift/Reduce

1. Explicación Teórica de Conflictos LALR(1)

Un conflicto Shift/Reduce (Desplazar/Reducir) ocurre cuando el parser no sabe si debe desplazar el siguiente token a la pila o reducir los símbolos actuales mediante una regla de producción.

En lugar de reescribir gramáticas complicadas con niveles infinitos de no terminales (E -> E + T -> T * F -> F), CUP permite usar gramáticas ambiguas naturales definiendo directivas explícitas de precedencia y asociatividad:

precedence left MAS, MENOS; // Menor precedencia, asocia por la izquierda

precedence left POR, DIV; // Mayor precedencia

precedence right POTENCIA; // Asocia por la derecha (ej. 2^3^2 = 2^(3^2))

precedence right UMINUS; // Menos unario (ej. -5 * 3)

4. Ejercicio Guiado: Resolución del Conflicto del "Dangling-Else"

El clásico conflicto de if (c1) if (c2) s1 else s2 se resuelve asignando mayor precedencia a ELSE sobre IF:

precedence nonassoc IF;
precedence nonassoc ELSE;

Esto fuerza al parser a asociar el else siempre al if más cercano inmediatamente anterior.

5. Ejercicio de Práctica (Firmas 40%)

Declara la tabla de precedencias en CUP para los operadores lógicos OR, AND y NOT unario, asegurando que NOT tenga la mayor precedencia y OR la menor. Pista: precedence right NOT;

3.3

Símbolos con Tipos y Valores Semánticos (`RESULT`)

1. Explicación del Manejo de Atributos Sintetizados en CUP

En CUP cada símbolo no terminal puede tener un tipo Java asignado (Integer, Double, String, o clases de nodos AST como NodoAST).

Para acceder al valor semántico de un símbolo hijo en el lado derecho de una producción se le asigna una etiqueta con dos puntos (ej. expr:a). La variable reservada RESULT contiene el valor retornado por la regla hacia el nodo padre:

expr ::= expr:a MAS expr:b {: RESULT = a + b; :}
      | expr:a MENOS expr:b {: RESULT = a - b; :}
      | MENOS expr:a {: RESULT = -a; :} %prec UMINUS;
4. Ejercicio Guiado: Calculadora con Tipos Flotantes (Double) 
terminal Double NUM_FLOAT;
non terminal Double expresion;

precedence left MAS, MENOS;
precedence left POR, DIV;

expresion ::= expresion:n1 MAS expresion:n2  {: RESULT = n1 + n2; :}
            | expresion:n1 DIV expresion:n2  {:
                if (n2 == 0.0) {
                    System.err.println("Error: División entre cero");
                    RESULT = 0.0;
                } else {
                    RESULT = n1 / n2;
                }
            :}
            | NUM_FLOAT:f {: RESULT = f; :};
3.4

Manejo y Recuperación de Errores Sintácticos en CUP

1. Métodos syntax_error y Símbolo Especial error

Por defecto, CUP aborta el análisis sintáctico al encontrar el primer error. Para que un compilador profesional reporte múltiples errores y continúe el análisis se sobreescriben los métodos en parser code y se usan producciones con el token especial error:

// Sobreescritura en parser code:

public void syntax_error(Symbol s) {

  System.err.println("Error sintáctico en Línea " + (s.left+1) + ", Col " + (s.right+1) + " cerca de: '" + s.value + "'");

}

Recuperación en Modo Pánico:

sentencia ::= error PUNTO_Y_COMA {: System.out.println("Recuperado tras ';' ignorando sentencia errónea."); :};

3.5

Proyecto Completo en NetBeans con Parser CUP y Swing

1. Integración en NetBeans: Generador Automático y GUI

Para compilar CUP dentro de Apache NetBeans sin usar comandos externos, creamos una clase auxiliar en Java que invoca directamente a la clase principal de CUP: 

package compilador;

public class GenerarParser {
    public static void main(String[] args) {
        String[] opcionesCUP = {
            "-destdir", "src/compilador",
            "-parser", "Parser",
            "-symbols", "sym",
            "src/compilador/Parser.cup"
        };
        try {
            java_cup.Main.main(opcionesCUP);
            System.out.println("¡Parser y sym generados exitosamente por CUP!");
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
